# Backup, repository and restore specification

**Status: proposed behavior, not a working backup system.** A backup is successful only if its set is immutable, verified, decryptable under escrowed keys, and restorable. Sources are Windows 10/11 files/folders; no agent, bare-metal imaging or CredSSP.

## Source and baseline rules

- Select host → SMB share → relative folder/file patterns. Support glob (`*`, `?`, `**`) with defined case rules for Windows; normalize separators and reject absolute, parent traversal, UNC injection, device names, trailing-dot/space aliases, symlink/junction escapes and 8.3 aliases where applicable. Default not to follow reparse points. Store normalized relative paths and explicit tombstones for deletions.
- Preserve file bytes, sizes, modified times and basic attributes; preserve ACLs only when both source capture and target restore support a verified round-trip. Registry hives, alternate data streams, owner/SACL, EFS, hard-link identity and application-consistent database state are **not promised** without explicit validated support; document outcomes per file and host. VSS supports snapshot consistency, not automatic application-level consistency.
- **Full:** capture all selected files, establish baseline/root. **Incremental:** compare with the last *successful verified backup of any type* in the same template/source chain. **Differential:** compare with last successful verified Full; restores require root Full + selected Differential. Incremental restore walks the root and ordered intervening sets. Warn at configurable chain depth, default 30.
- Per job/source detector: `mtime_size` (default fast heuristic; mtime alone is insufficient), `usn_journal` via allowlisted WinRM with explicit audited fallback to `mtime_size` or `hash_verify` as policy dictates, and `hash_verify` for strongest verification. Track USN journal ID/position and detect wrap/recreation; on discontinuity rescan rather than miss changes. File hashes on read protect against metadata-only false negatives. No baseline is chosen across tenants, repository keys or incompatible source definitions.
- Per-source options: VSS, detector, copy strategy, bandwidth cap, retries, credential ref and include/exclude. A changed source selection should force a new baseline or explicit reconciliation.

## Preflight, copy and commit

1. Validate tenant/policy, resolve credential in precedence order (job override → source override → host policy → credential group → global default), audit secret read, enforce lockout counter. Probe DNS/IP, WinRM (unless explicitly `smb_only`), SMB share/DFS, negotiated dialect/signing/encryption, repository free space/key availability and source snapshot capability. Check host/policy/global pause. Return typed actionable error with host/remediation on failure.
2. For NTFS, VSS is mandatory by default. Create through allowlisted WinRM template, persist provider ID and deadline, ensure worker can read the **snapshot view** through an authorized path before copying. If snapshot access fails, abort; do not silently copy live files. `smb_only` explicitly degrades consistency and disables VSS/USN/pre-post scripts. Delete in `finally` on completion/cancel/failure and periodically reap only snapshots with verified NetVault ownership/expired lease. A failed cleanup must be surfaced as an alert, not concealed by job success.
3. Copy via `CopyStrategy`: Windows robocopy when reachable over SMB, with return-code interpretation, `/Z`, bounded `/R` and `/W`, `/MT` and throttling; **never blindly use `/MIR` against a shared/live repository or incremental destination**. Linux uses a mature SMB client with explicit dialect/NTLMv2 or Kerberos and per-host concurrency; rsync-over-SMB is opt-in. Enforce connect/read/job deadlines, bounded retries with jitter, case/Unicode/long-path handling and finite bandwidth throttling. Remote allowlisted command arguments are encoded data, never interpolated script.
4. Stage in attempt-specific scratch/objects; split content into variable-size chunks, SHA-256 identify inside tenant/repository scope, compress with zstd, encrypt using unique AEAD nonce and per-repository data key, and write storage objects atomically (local rename or staged object + commit protocol). Reference existing chunks without re-encrypting them; authenticated metadata includes version, length and compression mode. Never use convergent cross-tenant encryption. Mirror mode disables chunk dedup but still encrypts and verifies.
5. Build candidate manifest with relative paths, metadata, content hashes, ordered chunk refs, deletions and baseline links. Verify all staged/existing chunks can be read/decrypted and integrity-checked, and optionally restore N random files to scratch for hash comparison. Seal manifest and commit backup set, refcounts, metrics, final state and audit in a DB transaction only after required verification. Handle DB/storage split with staged-object reconciliation: an orphan is never considered a completed backup; GC only after a safety window and set/manifest reconciliation.
6. Checkpoint at bounded file/second intervals. On lease expiry, worker reconciles snapshot record, staging and manifest, then resumes or fails cleanly; per-file stable IDs and idempotent writes prevent duplicates. `PARTIAL` retains per-source result and cannot silently become the baseline for a failed source.

## Retention and integrity

Compute GFS daily/weekly/monthly/yearly buckets in policy timezone with minimum keep; protect every dependency needed to restore retained increments/differentials and never remove the last known-good Full. Simulate prune and capacity effects before deletion; lock affected chains, decrement refs transactionally, and GC zero-ref chunks only after delay and orphan scan. Scrub checks manifest hashes, object presence, AEAD validation and sample restore; `repo scrub --verify` must prove a restore without decrypting the entire repository. Raise alert for missing keys, corrupt chunk and low capacity.

## Restore contract

Browse authorized sets as a tree; choose files/folders, original or alternative destination and `never`, `if_absent`, `replace` overwrite mode. Require typed confirmation of target resource before destructive replace; server rechecks RBAC, selected set chain, normalized paths, symlink/reparse safety, target permissions and available space. Stage decrypted files under a confined scratch root, verify content hashes, restore attributes/timestamps/ACL only if available, then atomically promote under each destination's policy. Never overwrite on hash/authorization failure. Remote restore over SMB uses scoped credential; log actor/target/selected entries and per-file result without secrets or optional sensitive filenames. Restore jobs use the same queue/deadline/audit semantics as backups.

## Error classes

`AuthFailed`, `HostUnreachable`, `ShareNotFound`, `SmbProtocolRejected`, `SnapshotError`, `CopyError`, `QuotaExceeded`, `BackendUnavailable`, `PreflightError`, `PolicyError` each expose retryable flag and operator remediation. Auth denial, invalid path and policy conflict are terminal; transient network disconnect, throttling or backend timeout are retryable within budgets. An entire fleet run can be `PARTIAL` without hiding failures.
